# rencal-app

The native GPUI app (`GPUI_PORT_PLAN.md`), built on `gpui-kit` (pinned exactly, see D1). It runs next to the Tauri app until cutover: binary `rencal-app`, single-instance socket `rencal-gpui`. Run it with `just app` (`just app '*'` logs debug; a comma-separated value narrows to targets containing those names). Backend logic stays in `rencal-core`; geometry, time and text logic go in the pure crates (§3.1), never here.

## Layout

- `main.rs`: startup order. Logging, single instance, the tokio runtime, `AppState`; then `Settings`, `UiState` and `ThemeStore` are installed before the first window opens, then `Plugins`, `Backend`, `Clock`, `Navigation`, `EventStore`, `SyncState`, `Providers` and the editing state (`editing::init`).
- `runtime.rs`: the `Tokio` global (D6; gpui-kit 0.7.1 ships no `gpui_tokio`). Backend futures and blocking IO run there; UI code awaits their `JoinHandle`s in `cx.spawn`. Never do file IO on the main thread after startup.
- `watchers.rs`: the GPUI side of `rencal-core`'s watchers, replacing the Tauri app's `state_bridge.rs`/`AppEvent`. `AppState` channels and callback watchers each get one `cx.spawn` loop that updates a global. External caldir changes bump `CaldirRevision`; the views that load caldir data observe it.
- `settings.rs`: `Settings` global (renCal's `config.toml`, caldir settings, system tz). Write renCal's config through `Settings::update_rencal` (persists only when the `Tokio` global exists, so tests never write) and caldir's through `Settings::set_time_format` / `set_default_reminders` / `set_default_calendar` / `set_calendar_dir`; the watchers reload edits made elsewhere.
- `ui_state.rs`: `UiState` (view, sidebar, group), JSON in the XDG state dir. View ids are strings so the view registry stays open.
- `theme/`: `ThemeStore` global (`mod.rs`), the theme selection port of `theme-settings.ts` (`selection.rs`), the gpui-kit projection (`bridge.rs`, §4.8) and embedded fonts. Components read tokens through `cx.ren_theme()`; gpui-kit's `cx.theme()` is only for stock gpui-kit components.
- `backend.rs`: the `Backend` global (`Arc<AppState>`), `Backend::read`/`write` (blocking caldir work on the runtime), the RPC ↔ `rencal_time` conversion (serde, since the app model mirrors the RPC types) and the event writes (`create_event`, `update_event`, `split_series`, …, taking `EventFields`). `None` in tests.
- `clock.rs`: `Clock` (current minute, viewer zone, today), ticking on minute boundaries and following `Settings::system_tz`. Never read `Utc::now()` for display; read the clock.
- `navigation.rs`: `Navigation` (active date). `navigate_to` is a deliberate jump: it bumps `version`, which views compare to recheck visibility (`docs/scroll-behaviour.md`); `set_active_date` only changes the date.
- `event_store.rs`: `EventStore` entity (`EventStore::global`): calendars, visible calendars (active group), range-based serialized loading (`ensure_loaded` only widens; views never wait), invites, the open (`active_event`) and agenda-selected (`selected_event`) event, and the optimistic edits (`replace_event`, `remove_events`, `insert_events`, `reconcile_create`). `revision` bumps with every events change; cache layouts on it.
- `sync_state.rs`: `SyncState` (port of `SyncContext`): preview/sync on start, on calendar changes, on window focus and when auto-sync is switched on; `sync_now` for `s`. A run that holds back mass deletions keeps the sync lock until `mass_delete.rs` (the main window's confirm dialog) confirms, discards or cancels.
- `accounts/`: `Providers` (the provider list, rescanned when a list opens, display names, icons, order) and `connect` (the connect dialog: provider list, setup, credentials, local-only calendar; the subscription dialog; `begin`/`connect_with_credentials`, which open browser sign-ins through a main-thread opener). Used by Settings › Accounts / Calendars, the create gate and the agenda's get-started state.
- `plugins/`: the `Plugins` global over `PluginManager` (list, catalog, install, uninstall; `revision` bumps when the plugin watcher reconciles), catalog previews (`preview`, fetched by `rencal_core::plugins::fetch_preview`: GPUI has no HTTP client on the desktop), the merged list (`list.rs`, pure), `PluginDetails` (shared by the settings sheet and the deep-link dialog) and `install_dialog` (`rencal://plugin/install`).
- `keymap.rs`: the shortcut table (fixture-tested against `tests/fixtures/shortcuts.json`) and its actions; `commands.rs`: the palette table (`palette_commands.json`). `actions.rs` binds both and handles the app-level actions.
- `views/`: the open view registry (`VIEWS`, keyed by `UiState::calendar_view`), `InfiniteAxis` + `WeekSnap` (`axis.rs`), month, week and board views, `measure` (a view sizes itself from last frame's bounds), `ViewEvents` (the loaded events plus the draft, drag preview and month create selection, with their `EventRole`s) and `interact.rs` (event blocks: popover, drag, menu; day backgrounds: navigate, create).
- `editing/` (Phase 4): `commands.rs` is every event write (save with the recurrence-scope dialog, delete, duplicate, RSVP, create), optimistic with rollback and error toasts; `dialogs.rs` the scope/delete dialogs; `draft.rs` `DraftState` (compose text parsing, the new-event popover, `open_day_draft`); `form.rs` `EventForm`, the editor in the popover, sheet and compose card, with its inputs in `fields/` (`ComboState`, the input-as-combobox, plus time, date, time zone, reminders, attendees); `popover.rs` the event popover / narrow sheet; `compose.rs` the sidebar compose input, magic outlines, card and fly animation; `drag.rs` drag to reschedule / create; `context_menu.rs` the right-click menus. `mod.rs` has `ClickGuard`, `toast_error` and the create gate.
- `sidebar/`: toolbar, `Minical`, `Agenda` (GPUI `list` of day sections; ghost section, regroup anchoring, `Tab` selection). `toolbar.rs`: controls shared by the header and the narrow sidebar toolbar.
- `palette.rs` (command palette, go-to-date, theme/group pages), `search.rs` (search palette, `jump_to_event`), `shortcuts_overlay.rs`: overlays on gpui-kit `Command`/`Dialog`/`Sheet`. A chosen command runs after the dialog closes and focus is restored, so window-level actions reach the main window.
- `ui/`: theme tokens as GPUI values (`Palette`, `metric`, `text_size`, typography `Role`s), resolved `Fonts`, event paint (`event_paint.rs`, §4.6), key chips and `anchors.rs`, last frame's geometry (event blocks, drop targets, scroll containers, named anchors) that replaces the old DOM lookups; `image.rs` decodes the backend's `data:` URLs (plugin provider icons, local previews). `assets.rs`: renCal's SVG icons (`RenIcon`, tinted) and multi-colour images (`RenImage`, drawn with `img`) over gpui-kit's bundle.
- `deep_links.rs`: `rencal://` intake (launch args, Linux single-instance socket, macOS `open_urls`) into `AppState`'s inbox; event links open the event, plugin install links the install dialog.
- `windows/`: main window (sidebar, header, current view, window-level actions), settings window, the fatal-error window, and shared chrome (`window_options`, `drag_region`). `windows/settings_window/` has one view per page (`general`, `accounts`, `calendars` + `groups`/`calendar_dialogs`, `reminders`, `themes`, `plugins`), built fresh when its tab opens, and the shared `controls` (page body, select, checkbox, "⋯" menu).

## Rules

- Import GPUI through `gpui_kit` (`use gpui_kit::{…}`), never a `gpui` crate. Test modules import what they use; `use gpui_kit::*` with `test-support` shadows `#[test]`.
- Globals change only when a value changes (`Settings::update`, `UiState::update`, `ThemeStore` compare before setting), so observers can refetch freely.
- UI tests: `#[gpui_kit::test]` with `test_support::init` for the globals (frozen clock: Wed 2026-10-07 10:00 UTC; empty `EventStore` without a backend, fill it with `set_test_events`). Nothing in a test may write the user's files (`UiState::init_with(…, None, cx)`). Tests that load through a real `AppState` (`event_store::tests`) need `cx.executor().allow_parking()` and a tokio runtime.
- Views read events and calendars from `EventStore` and colours through `ui::event_paint`; never call `rencal_core::caldir` from a view. Pure maths (lanes, snapping, time) belongs in the domain crates.
- GPUI can't paint a border on a quad no taller (or wider) than the border; draw hairlines as background quads (see the week view's current-time line).
- Key contexts: calendar shortcuts bind to `CalendarView && !Input` (so typing in any gpui-kit input never triggers them) and, unless `allow_while_event_open`, also `!event_open`, which the main window sets while the popover is open. Text inputs inside the main window are fine as long as the bindings keep `!Input`.
- Event writes go through `editing::commands`, never `backend` directly from UI code. A click handler that navigates checks `ClickGuard::swallowed` (the release after a drag, or the click that closed the popover).
- Event blocks record themselves with `ui::anchors::event_anchor` (via `views::interact::event_block`); a background's press handler ignores presses where `Anchors::event_at` finds a block, instead of relying on event propagation order. Drop targets record `drop_anchor`, scrollable views `scroll_anchor`.
- GPUI fires focus listeners only in the active window: UI tests that rely on focus call `window.activate_window()` (see `editing::tests`). `ScrollHandle::scroll_to_item` is dropped on a scroll container's first frame; `ComboState` waits a frame before revealing.
- Dialogs with text inputs (gpui-kit `open_dialog`): the dialog focuses itself as it opens, so focus the input after `open_dialog`; a single-line input passes Enter on to the dialog's Confirm, which closes the dialog by default, so submit from the dialog's `on_ok` (returning `false`) rather than from `InputEvent::PressEnter` (see `settings_window::calendar_dialogs`).
- GPUI calls a `ListState` scroll handler while the list state is borrowed: defer anything that reads the list (`sidebar::agenda`).
- Building needs the nix dev shell (`flake.nix` adds GPUI's xkbcommon/Wayland/X11/Vulkan libraries); CI installs the apt equivalents.
